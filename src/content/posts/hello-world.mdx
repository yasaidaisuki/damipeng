We ran six API replicas behind a load balancer. Background workers finished a job, emitted a WebSocket
event — and that event only reached clients connected to whichever replica the worker happened to talk
to. Five out of six users were waiting on a spinner that would never resolve.

The fix was to stop treating the socket server as a single place. Workers publish to a channel; every
replica subscribes and forwards to its own connected clients.

```ts
// worker: publish instead of emitting locally
await redis.publish('ws:events', JSON.stringify({ room, event, payload }));

// every API replica
sub.subscribe('ws:events');
sub.on('message', (_, msg) => {
  const { room, event, payload } = JSON.parse(msg);
  io.to(room).emit(event, payload);
});
```
